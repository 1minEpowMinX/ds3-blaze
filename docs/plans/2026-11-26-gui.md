# GUI and workspace split: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** carry out [docs/design/gui.md](../design/gui.md): a window players can follow, built on a workspace whose core the window, the command line and the tests share.

**Architecture:** the work runs in the seven stages the spec lists, each on its own branch merged into `main` when CI passes. This document holds the roadmap of all stages and the step-by-step tasks of the stage that is next. A stage's tasks are written when the stage before it has been merged, because they name files, types and signatures that only exist from then on.

**Tech Stack:** Rust (edition 2024, stable), Cargo workspace, tokio, blaze-ssl-async, tdf; later clap and eframe. Windows only. PowerShell for the repository tools.

## Global constraints

- The spec [docs/design/gui.md](../design/gui.md) is the source of truth; where this plan and the spec disagree, the spec wins and the plan is corrected.
- One branch per stage, named `<type>/<name>` with a type from `$Types` in `tools/check-commits.ps1`; merged into `main` with `git merge --no-ff`. Nothing is committed to `main` directly; the `commit-msg` hook refuses it (enable hooks with `git config core.hooksPath .githooks`).
- Commit subjects follow Conventional Commits: imperative, lower-case start, no final full stop. Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Before each commit: `tools/check-clean.ps1` passes; from `ds3-blaze/`, `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings` and `cargo test` pass.
- Rust docstrings are third person ("Returns the …"), one summary sentence first, facts about the implementation only, every parameter and the return value described. Comments explain why, in the present tense.
- Prose and documents are in English, British or American spelling kept consistent within a file, few dashes.
- Text never repeats a value the code owns (ports, names, lists): it names the constant or the declaration instead.
- `cargo` must be on `PATH` in the shell that runs the steps.
- A stage that removes or changes a command updates the README, the Nexus page (`docs/nexus/description.bbcode.txt`) and the guides that use it in the same branch. Until stage 6 the command line's executable keeps the name `ds3-blaze.exe`.

## Stage 2: protocol test

Merged into `main` on 2026-11-26 (`ae289fb`).

Branch `test/protocol-test` from `main`. The core gets one entry point that binds the three services and stops them together; the client sequence of `selftest` becomes a `cargo test` that starts its own server on free ports; the `selftest` command, its CI step and its mentions in the documents go.

`Server::start` binds every listener before it returns. A port in use therefore fails the call itself, and a test can ask for port 0 and read back the port the system picked. The redirector, the Blaze configuration and the QoS XML are built from the bound ports, not from the requested ones.

`ServerHandle::stop` ends the accept loops at once, which frees the ports, and ends every session task. A connection's socket closes when its writer task ends, which happens once nothing holds the session's sender any more: at once for a session outside any game, and for a logged-in player once the matchmaking or join timers holding the server's state have run out (at most `JOIN_TIMEOUT`). The CLI never calls `stop`; the GUI does from stage 6 on, and stage 3 closes these sockets at once if the GUI needs it.

### Task 1: `Server::start` and `ServerHandle`

**Files:**
- Create: `ds3-blaze/core/src/server.rs`
- Modify: `ds3-blaze/core/src/lib.rs` (module), `ds3-blaze/core/src/redirector.rs`, `ds3-blaze/core/src/blaze.rs`, `ds3-blaze/core/src/qos.rs` (`run` becomes `serve` over bound sockets), `ds3-blaze/cli/src/main.rs` (port constants and `serve`)

**Interfaces:**

```rust
/// Accepts sessions on `listener` until it fails, closing connections from
/// addresses the configuration does not admit; each session ends when `stop`
/// is cancelled.
pub async fn serve(
    listener: TcpListener,
    config: Arc<Config>,
    stop: CancellationToken,
) -> std::io::Result<()> {
    log!("blaze", "listening on {} (plain TCP)", listener.local_addr()?);
    if config.only_listed {
        log!(
            "blaze",
            "accepting only this machine, {} and the --player addresses",
            config.advertise
        );
    }
    let next_id = Arc::new(AtomicU32::new(1));
    loop {
        let (tcp, peer) = listener.accept().await?;
        if !config.admits(peer_ipv4(peer)) {
            log!("blaze", "{peer}: refused, address not listed");
            continue;
        }
        let id = next_id.fetch_add(1, Ordering::Relaxed);
        tokio::spawn(
            stop.clone()
                .run_until_cancelled_owned(serve_session(tcp, peer, id, config.clone())),
        );
    }
}
```

```rust
/// Serves the HTTP part on `http` and the UDP probe echo on `udp` until either
/// fails; each HTTP connection ends when `stop` is cancelled.
///
/// `advertise` is the address written into the XML as the probe target.
pub async fn serve(
    http: TcpListener,
    udp: UdpSocket,
    advertise: Ipv4Addr,
    stop: CancellationToken,
) -> std::io::Result<()> {
    let udp_addr = udp.local_addr()?;
    log!(
        "qos",
        "listening on {} (HTTP) and {udp_addr} (UDP)",
        http.local_addr()?
    );
    tokio::try_join!(accept_http(http, advertise, udp_addr.port(), stop), echo(udp))?;
    Ok(())
}

async fn accept_http(
    listener: TcpListener,
    advertise: Ipv4Addr,
    udp_port: u16,
    stop: CancellationToken,
) -> std::io::Result<()> {
    loop {
        let (tcp, peer) = listener.accept().await?;
        tokio::spawn(
            stop.clone()
                .run_until_cancelled_owned(serve_http(tcp, peer, advertise, udp_port)),
        );
    }
}
```

```rust
//! The three services `serve` runs (redirector, main Blaze server, QoS), bound
//! together and stopped together.

use crate::{blaze, models, qos, redirector};
use std::net::Ipv4Addr;
use std::sync::Arc;
use tokio::net::{TcpListener, UdpSocket};
use tokio::task::JoinHandle;
use tokio_util::sync::{CancellationToken, DropGuard};

/// Port the game's redirector lookup connects to.
pub const REDIRECTOR_PORT: u16 = 42127;
/// Default port of the main Blaze server handed out in the redirect.
pub const DEFAULT_BLAZE_PORT: u16 = 42128;
/// Default QoS HTTP port; EA's QoS servers use the same one.
pub const DEFAULT_QOS_HTTP_PORT: u16 = 17502;
/// Default QoS UDP probe port; EA's QoS servers use the same one.
pub const DEFAULT_QOS_UDP_PORT: u16 = 17499;

/// Ports of the three services; 0 lets the system pick a free one.
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct Ports {
    pub redirector: u16,
    pub blaze: u16,
    pub qos: qos::Ports,
}

impl Ports {
    /// Ports that let the system pick a free one for every service.
    pub const ANY: Ports = Ports {
        redirector: 0,
        blaze: 0,
        qos: qos::Ports { http: 0, udp: 0 },
    };
}

impl Default for Ports {
    /// Returns [`REDIRECTOR_PORT`], [`DEFAULT_BLAZE_PORT`],
    /// [`DEFAULT_QOS_HTTP_PORT`] and [`DEFAULT_QOS_UDP_PORT`].
    fn default() -> Self {
        Ports {
            redirector: REDIRECTOR_PORT,
            blaze: DEFAULT_BLAZE_PORT,
            qos: qos::Ports {
                http: DEFAULT_QOS_HTTP_PORT,
                udp: DEFAULT_QOS_UDP_PORT,
            },
        }
    }
}

/// Settings of a server started with [`Server::start`].
pub struct Config {
    /// Address every listener binds to.
    pub bind: Ipv4Addr,
    /// Address handed to clients as this machine's (redirect, telemetry, QoS).
    pub advertise: Ipv4Addr,
    pub ports: Ports,
    /// Display name of a player connecting from this machine or from `advertise`.
    pub player_name: String,
    /// Display names of players connecting from other addresses.
    pub player_names: Vec<(Ipv4Addr, String)>,
    /// Whether Blaze accepts connections only from this machine, `advertise`
    /// and the addresses in `player_names`.
    pub only_listed: bool,
}

/// Entry point that starts the three services.
pub struct Server;

impl Server {
    /// Binds the redirector, Blaze and QoS listeners on `config.bind` and
    /// serves them in a background task.
    ///
    /// `config` holds the addresses, ports and player settings. The redirect,
    /// the Blaze configuration and the QoS XML carry the bound ports, which
    /// differ from `config.ports` where those are 0. Returns a handle to the
    /// running server, or the error of the first listener that cannot be bound.
    pub async fn start(config: Config) -> std::io::Result<ServerHandle> {
        let redirector = TcpListener::bind((config.bind, config.ports.redirector)).await?;
        let blaze = TcpListener::bind((config.bind, config.ports.blaze)).await?;
        let qos_http = TcpListener::bind((config.bind, config.ports.qos.http)).await?;
        let qos_udp = UdpSocket::bind((config.bind, config.ports.qos.udp)).await?;
        let ports = Ports {
            redirector: redirector.local_addr()?.port(),
            blaze: blaze.local_addr()?.port(),
            qos: qos::Ports {
                http: qos_http.local_addr()?.port(),
                udp: qos_udp.local_addr()?.port(),
            },
        };
        let instance = redirector::Instance {
            ip: config.advertise,
            port: ports.blaze,
            secure: false,
        };
        let blaze_config = Arc::new(blaze::Config {
            advertise: config.advertise,
            qos: models::QosHttp {
                host: config.advertise,
                port: ports.qos.http,
            },
            player_name: config.player_name,
            player_names: config.player_names,
            only_listed: config.only_listed,
            games: Default::default(),
        });
        let stop = CancellationToken::new();
        let token = stop.clone();
        let advertise = config.advertise;
        let task = tokio::spawn(async move {
            let services = async {
                tokio::try_join!(
                    redirector::serve(redirector, instance, token.clone()),
                    blaze::serve(blaze, blaze_config, token.clone()),
                    qos::serve(qos_http, qos_udp, advertise, token.clone()),
                )
                .map(|_| ())
            };
            let result = token.run_until_cancelled(services).await.unwrap_or(Ok(()));
            // A service that failed ends the sessions of the other two as well.
            token.cancel();
            result
        });
        Ok(ServerHandle {
            ports,
            stop: stop.clone(),
            task,
            _stop_on_drop: stop.drop_guard(),
        })
    }
}

/// Running server returned by [`Server::start`]; dropping it stops the server.
pub struct ServerHandle {
    ports: Ports,
    stop: CancellationToken,
    task: JoinHandle<std::io::Result<()>>,
    _stop_on_drop: DropGuard,
}

impl ServerHandle {
    /// Returns the ports the listeners are bound to.
    pub fn ports(&self) -> Ports {
        self.ports
    }

    /// Closes the listeners and ends every session task.
    pub fn stop(&self) {
        self.stop.cancel();
    }

    /// Waits until the server ends and returns the error of the service that
    /// failed, or `Ok` after [`ServerHandle::stop`].
    pub async fn finished(self) -> std::io::Result<()> {
        self.task.await.map_err(std::io::Error::other)?
    }
}
```

## Stage 3: events, snapshot and player book

Branch `refactor/events` from `main`. The core stops printing: every log line becomes an event, which the CLI prints. The state a window shows is read on demand from `ServerHandle::snapshot()`, and the player names and admission rules move into a `PlayerBook` that can change while the server runs.

The event channel is one per process, in `ds3_blaze_core::event`, like the log file it sits beside: `log!` is called from every module and every task, and passing a sender down to each call site would touch most functions for no gain while the process runs one server. `ServerHandle::events()` subscribes to that channel. `Event::Log` carries a `LogLine` with the local time, so a line printed later still shows the moment it was written, and the console and the file render it with the same `Display`.

Stage 2 expected a logged-in player's socket to stay open after `stop` until the server's timers let go of the session's sender. A test shows it closes at once: dropping the session aborts its matchmaking timer and removes the player from the games and the logged-in users, which leaves no sender behind. The session's writer task now also ends on the stop token, so the socket closes whatever holds a sender in the future.

```rust
/// Returns `Ok` when `name` has a length within [`NICKNAME_LENGTH`] and only
/// ASCII letters, digits, `-` and `_`, or the reason it does not.
pub fn check_nickname(name: &str) -> Result<(), String> {
    if let Some(c) = name
        .chars()
        .find(|c| !(c.is_ascii_alphanumeric() || *c == '-' || *c == '_'))

        return Err(format!(

            NICKNAME_LENGTH.start(),
            NICKNAME_LENGTH.end()
        ));
    }
    Ok(())
}
```
