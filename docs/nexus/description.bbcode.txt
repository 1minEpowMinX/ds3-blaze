[size=6][b]Short description[/b][/size]
Play Dead Space 3 co-op with a friend without going through EA's servers. One of you runs a small server, both of you join the same VPN, and the game connects you directly.

[size=6][b]The problem[/b][/size]
Co-op still goes through EA's servers, and for many players it ends in [i]Failed to join game[/i] or a kick some twenty seconds into the session.

EA's servers only introduce the two players; the game itself runs peer to peer, straight between the two PCs. When either player sits behind a provider-level NAT (CGNAT) or a strict router, the PCs cannot reach each other, and EA's NAT traversal cannot get through it either. The servers are aging too: two of EA's four quality-of-service sites no longer answer.

[size=6][b]How it works[/b][/size]
ds3-blaze stands in for the EA servers that bring players together: login, game rooms, matchmaking and the network test. It hands each game the other player's VPN address, so the game traffic travels inside the VPN tunnel and NAT never comes into it.
[list]
[*]The game is launched through the EA App as usual. The mod only changes which server the game asks for a partner.[/*]
[*]No game file is touched. One line in the Windows [i]hosts[/i] file points the game at the server, and one command takes it out again.[/*]
[*]The server never contacts EA. The game's login token is accepted as it is and goes nowhere.[/*]
[/list]
[size=6][b]What works[/b][/size]
[list]
[*]Going online and opening the co-op menu[/*]
[*]The host's game: create, play, quit with a save[/*]
[*]The guest joining through [b]Quick Match[/b] into a public game[/*]
[*]The guest joining through an [b]EA App invite[/b] into a private game[/*]
[/list]
Tested over Radmin VPN between two PCs thousands of kilometers apart, on different networks.

[size=6][b]Requirements[/b][/size]
[list]
[*]Dead Space 3 on PC for both players, launched through the EA App. Tested on the Steam version.[/*]
[*]Both PCs in one VPN network. Tested with [url=https://www.radmin-vpn.com/]Radmin VPN[/url] (free); any VPN that puts both PCs on one subnet should do.[/*]
[*]Administrator rights for one step: editing the [i]hosts[/i] file.[/*]
[/list]
[size=6][b]Installation[/b][/size]
Both players extract the archive to any folder; it does not go into the game folder. Open PowerShell in that folder (in Explorer: right-click the empty space in the folder > [i]Open in Terminal[/i]). [b]Back up your saves before the first session.[/b]

Both players first check the connection between the two PCs, at the same time, each with the other's VPN address:
[code].\ds3-blaze.exe p2p-check --peer <friend's VPN address>[/code]
[b]Host[/b]
[list=1]
[*]Start the server and leave its window open:
[code].\ds3-blaze.exe serve --bind 0.0.0.0 --advertise <your VPN address> --name <your name> --player <friend's VPN address>=<friend's name>[/code][/*]
[*]In a PowerShell window run as administrator, in the same folder:
[code].\ds3-blaze.exe hosts enable[/code][/*]
[*]Start the game, go online in co-op and create a game. A [b]public[/b] game lets your friend in through Quick Match; a [b]private[/b] one takes invites only, so invite them through the EA App.[/*]
[/list]
[b]Guest[/b]
[list=1]
[*]In a PowerShell window run as administrator, in the archive folder:
[code].\ds3-blaze.exe hosts enable --address <host's VPN address>[/code][/*]
[*]Start the game, go online in co-op, and either pick Quick Match or accept the host's invite in the EA App. Quick Match keeps searching for a while, so you may start it a little before the host's game is up.[/*]
[/list]
The README inside the archive covers every command and option.

[size=6][b]Going back to EA's servers[/b][/size]
Both players run, as administrator:
[code].\ds3-blaze.exe hosts disable[/code]
Then the folder can be deleted. While the entry is in place, that PC reaches only the ds3-blaze server, not EA's.

[size=6][b]Troubleshooting[/b][/size]
[list]
[*][b]p2p-check[/b] shows in which direction packets do not arrive, and why: the wrong network adapter, a VPN network that Windows files as [i]Public[/i] (where inbound traffic is blocked), or a firewall rule. Fix what it reports and run it again on both PCs.[/*]
[*]If Windows asks whether to let [i]ds3-blaze.exe[/i] through the firewall, allow it.[/*]
[*]The server writes a log to the [i]logs[/i] folder next to it, showing how far each player got. Logs contain friend lists and IP addresses: if you attach one to a bug report, send it privately rather than posting it.[/*]
[/list]
[size=6][b]Known limitations[/b][/size]
[list]
[*][b]No host migration.[/b] When the host quits, the game ends for the guest too.[/*]
[*][b]A dropped connection is not restored.[/b] Handling disconnects is the next stage of work.[/*]
[*][b]Invites need exactly two players on the server.[/b] The server knows players by the address they connect from, not by EA account, so it matches an invite to the host only while the two of you are the only players on it. Quick Match has no such restriction.[/*]
[*]Names in game come from [i]--name[/i] and [i]--player[/i], not from your EA profile.[/*]
[/list]
